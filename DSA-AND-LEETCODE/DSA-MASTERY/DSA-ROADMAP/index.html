Part A

Universal Problem-Solving Framework

This is your reusable cheat sheet. Before you ever look at a problem's solution, run it through these steps every single time — both while learning and in a real interview under the clock.

Step 1 — Read and Deconstruct the Problem

Before writing a single line of code, extract these six things from the problem statement in writing (or out loud in an interview):

1a
What is the input?

Name the type (array, string, integer, graph, matrix?) and its shape. E.g., "input is a 0-indexed integer array nums of length n."

1b
What is the output?

A single value? A list? An index? A boolean? Write it down. Don't assume.

1c
What are the constraints?
  • Size constraints — what is n? Is n ≤ 20? ≤ 10⁵? ≤ 10⁹? (These directly hint at expected time complexity — see Step 2.)
  • Value constraints — are values negative? Can they be zero? Are they sorted? Unique?
  • Type constraints — can the array be empty? Can strings contain spaces/special chars?
1d
What are the edge cases?
  • Empty input ([], "", 0, None)
  • Single element
  • All same values
  • Sorted / reverse sorted
  • Max possible value of n
  • Negative numbers
  • Integer overflow (rare in Python, but note for Java/C++)
1e
What are the hidden assumptions?

Problems often hide key assumptions. Ask: "Can I modify the input? Can I use extra space? Do I need the lexicographically first / smallest / optimal result?" These all affect which algorithm you choose.

1f
Rephrase the problem in one sentence.

If you can't summarize it cleanly in your own words, you don't fully understand it yet. This is your verification step.

Step 3 — Brute Force → Optimize Checklist

Never jump straight to the optimal solution. Follow this escalation path every time:

3A
Brute Force First (Always)

What is the most obvious, naive solution — even if it's O(n³)? Write it down in pseudocode. This anchors your understanding and gives you a reference to verify your optimized solution against.

3B
Identify what's repeated / redundant
  • Are you recomputing the same subproblem? → Memoization / DP
  • Are you re-scanning the same subarray? → Sliding window / prefix sum
  • Are you doing O(n) work inside an O(n) loop unnecessarily? → Two pointers / sorting
  • Are you searching in O(n) when the data is sorted? → Binary search
3C
Apply the technique → code it → verify same output as brute force

Run both solutions on your test cases to confirm correctness before claiming optimization.

3D
Analyze space trade-offs

Many time optimizations cost extra space (hash maps, memos, prefix arrays). Know your trade-off explicitly: "I'm trading O(n) space for O(1) time per lookup."

Follow this structure word-for-word in every mock and real interview. Silence is the enemy — talk through your thinking out loud at every step.

②
Brute Force (1–2 min)

"The simplest approach I can think of is [brute force]. This would be O(n²) time and O(1) space. I won't code this, but I'll use it as a reference. Let me think about how to improve it."

③
Optimize (3–5 min)

"I notice that [repeated work / sorted input / constraint]. That suggests I could use [technique]. The key insight is [X]. Let me walk through the approach before coding: [pseudocode / logic steps]."

④
Code (10–15 min)

"I'll now code this up. I'll narrate as I go." Write clean, readable code with variable names that are self-documenting. Add a one-line comment at each key step.

⑤
Test (3–5 min)

"Let me trace through my code with the given example first… [trace]. Now let me test edge cases: empty array, single element, all same values."

⑥
Complexity Analysis (1–2 min)

"Time complexity is O(n) because [reason]. Space complexity is O(1)/O(n) because [reason]." Always explain why, not just what.

Step 5 — Testing Checklist

Run through these test cases for every problem before submitting:

  • The given example(s) from the problem statement
  • Empty input: [], "", 0, None — does it crash or return sensible default?
  • Single element / single character
  • All same values (e.g., [1,1,1,1])
  • Already sorted / reverse sorted array
  • Maximum n — will it TLE? Mentally estimate: 10⁸ ops ≈ 1 second in Python
  • Negative numbers, zero values
  • Two elements (minimum non-trivial case)

Step 6 — "I'm Stuck" Decision Tree

🔴 You're stuck. Run through this order:

  1. Re-read the constraints. Did you miss n ≤ 20? That changes everything.
  2. Draw a small example (5–6 elements). Trace through manually. Pattern emerge?
  3. Ask: "Have I seen a sub-problem like this before?" (prefix sum? two pointer? recursion?)
  4. Try sorting the input. Many problems become trivial when sorted.
  5. Think in reverse. Can I work backwards from the answer?
  6. Reduce the problem. What if n=1? n=2? n=3? Can I generalize?
  7. Try a hash map. If you need O(1) lookup, a hash map almost always helps.
  8. Think tree/graph. Is this actually a graph problem in disguise? (islands, dependencies)

  → Still stuck after 15 min? Note the pattern, look at the solution, UNDERSTAND it,
    re-implement from scratch without looking, and add it to your revision queue.

Step 7 — Common Traps by Difficulty

Easy

Easy Problem Traps

  • Off-by-one errors in array indices
  • Forgetting to handle the empty input case
  • Using == instead of is for None comparison
  • Modifying a list while iterating over it
  • Not returning anything (missing return statement)
  • Using a sorted() when you need in-place sort
Medium

Medium Problem Traps

  • Failing to handle duplicate values in two-pointer / binary search
  • Incorrectly initializing DP table (wrong base case kills everything)
  • Window shrink condition wrong in sliding window
  • Stack/queue using wrong data structure (list vs deque)
  • Graph problems: forgetting to mark visited → infinite loop
  • Confusing 0-indexed vs 1-indexed DP transitions
Hard

Hard Problem Traps

  • Choosing wrong DP state definition (makes transitions impossible)
  • Greedy fails: not proving the greedy choice is safe
  • Graph: using BFS when DFS needed or vice versa
  • Segment trees: lazy propagation not implemented
  • Forgetting to reset state in backtracking (not un-choosing)
  • Wrong time complexity analysis → TLE on submission

Module 0.7 — Basic Recursion (Critical Prerequisite)

Recursion is a function calling itself. It has two non-negotiable parts: a base case (when to stop) and a recursive case (calling itself with a simpler input). Missing the base case = infinite loop = crash.

# ── FACTORIAL — classic recursion intro ────────────────────────
def factorial(n):
    # Base case: stop here
    if n == 0 or n == 1:
        return 1
    # Recursive case: call self with smaller input
    return n * factorial(n - 1)

print(factorial(5))  # 120
# Call stack: factorial(5) → 5 * factorial(4) → 5*4*factorial(3) → … → 1

# ── FIBONACCI — exposing the problem with naive recursion ───────
def fib_naive(n):
    if n <= 1:
        return n
    return fib_naive(n-1) + fib_naive(n-2)
# This is O(2^n) — exponential time. fib_naive(50) will freeze your computer.

# FIX: Memoization (cache results you've already computed)
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]
# Now O(n) — linear time.

# OR use Python's built-in cache decorator
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)

# O(1): No loop, just direct access
def get_first(nums):
    return nums[0]  # O(1) time, O(1) space

# O(n): One loop
def find_max(nums):
    best = nums[0]
    for x in nums:  # runs n times
        best = max(best, x)
    return best   # O(n) time, O(1) space

# O(n²): Two nested loops
def has_duplicate_brute(nums):
    for i in range(len(nums)):         # outer: n times
        for j in range(i+1, len(nums)): # inner: ~n times
            if nums[i] == nums[j]:
                return True
    return False
# O(n²) time, O(1) space

# O(n) with O(n) space — a common trade-off
def has_duplicate_fast(nums):
    seen = set()          # O(n) space
    for x in nums:        # O(n) time
        if x in seen:     # O(1) lookup
            return True
        seen.add(x)
    return False
# O(n) time, O(n) space — much faster for large n!

🔬 Worked Example: Two Sum (LeetCode #1)

Let's apply the full Part A framework to the first and most famous DSA problem. You will see this exact problem structure repeated throughout the roadmap for every new topic.

Framework Application — Two Sum

Problem: Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target. Each input has exactly one solution. You may not use the same element twice.

1
Step 1 — Deconstruct

Input: int array nums (length n), int target. Output: list of 2 indices [i, j]. Constraints: exactly one solution exists, can't reuse same index. Edge cases: n=2 (minimum), negative numbers, target is sum of first+last.

2
Step 2 — Identify Pattern

"Find pair that sums to target" → Two Pointers or Hash Map. No sorting requirement → Hash Map wins here (no index scrambling). n ≤ 10⁴ → O(n) is fine.

3
Step 3 — Brute → Optimize

Brute: for each pair (i,j), check if nums[i]+nums[j]==target → O(n²). Optimize: for each element x, I need to find (target - x). Store seen numbers in a hash map → O(1) lookup → O(n) total.

4
Step 4 — Talk through it

"I'll scan left to right. For each nums[i], I compute complement = target - nums[i]. If complement is already in my hash map, return both indices. Otherwise, store nums[i] → i in the map."

5
Step 5 — Test plan

Test: [2,7,11,15] target=9 → complement of 2 is 7, not in map → add 2. Complement of 7 is 2, found at index 0 → return [0,1]. ✓ Edge: [3,3] target=6 → complement of first 3 is 3, not in map → add it. Complement of second 3 is 3, found at index 0 → [0,1]. ✓

# ── TWO SUM — Full solution with framework in comments ──────────

def two_sum(nums: list[int], target: int) -> list[int]:
    """
    Given nums and target, return indices [i, j] where nums[i] + nums[j] == target.
    
    Approach: Hash Map — store each number → its index as we scan.
    For each number, check if complement (target - num) was already seen.
    
    Time:  O(n)   — one pass through array
    Space: O(n)   — hash map stores up to n elements
    """
    
    # ── STEP 1: Set up our "memory" (hash map) ──────────────────
    seen = {}  # maps: number → index where we saw it
    
    # ── STEP 2: Scan left to right ──────────────────────────────
    for i, num in enumerate(nums):
        
        # ── STEP 3: What do we NEED to complete the pair? ───────
        complement = target - num
        
        # ── STEP 4: Did we already see the complement? ──────────
        if complement in seen:
            return [seen[complement], i]  # found it! return both indices
        
        # ── STEP 5: Haven't seen complement yet, store current num ─
        seen[num] = i
    
    return []  # problem guarantees a solution, so we won't reach here


# ── TESTS ───────────────────────────────────────────────────────
print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
print(two_sum([3, 2, 4], 6))         # [1, 2]
print(two_sum([3, 3], 6))             # [0, 1]

Module 1.1 — Arrays and Prefix Sums

An array is your most fundamental data structure. Most DSA problems are ultimately array problems in disguise. The prefix sum technique lets you answer "sum of elements from index i to j" in O(1) after O(n) preprocessing.

# ── PREFIX SUM — the single most useful array trick ────────────
# Problem: Given queries asking "what's the sum from index l to r?",
# answer each in O(1) instead of O(n).

def build_prefix(nums):
    n = len(nums)
    prefix = [0] * (n + 1)   # prefix[i] = sum of nums[0..i-1]
    for i in range(n):
        prefix[i+1] = prefix[i] + nums[i]
    return prefix

def range_sum(prefix, l, r):
    # Sum of nums[l..r] inclusive
    return prefix[r+1] - prefix[l]  # O(1)!

nums = [2, 3, 1, 5, 4, 2]
prefix = build_prefix(nums)
print(range_sum(prefix, 1, 3))  # 3+1+5 = 9
print(range_sum(prefix, 0, 5))  # 2+3+1+5+4+2 = 17

# ── WHY THIS WORKS ─────────────────────────────────────────────
# prefix[r+1] = sum of nums[0..r]
# prefix[l]   = sum of nums[0..l-1]
# Subtracting gives sum of nums[l..r]  ← brilliant!

Module 1.2 — Two Pointers

Two pointers is a technique where you maintain two indices (usually left and right) and move them toward each other or in the same direction. It eliminates a nested loop, turning many O(n²) problems into O(n).

When to use: Sorted array + find pair/triplet with property. Or: in-place array manipulation (remove elements, reverse).

# ── PATTERN 1: Opposite ends → converge toward center ──────────
# Problem: Two Sum II — sorted array, find pair that sums to target

def two_sum_sorted(numbers, target):
    left, right = 0, len(numbers) - 1  # start at both ends
    
    while left < right:
        s = numbers[left] + numbers[right]
        
        if s == target:
            return [left + 1, right + 1]  # 1-indexed answer
        elif s < target:
            left += 1    # sum too small → move left pointer right (bigger value)
        else:
            right -= 1   # sum too big  → move right pointer left (smaller value)
    
    return []

# Time: O(n), Space: O(1) — vs O(n²) brute force!

# ── PATTERN 2: Same direction → fast & slow ─────────────────────
# Problem: Remove Duplicates from Sorted Array (in-place)

def remove_duplicates(nums):
    if not nums:
        return 0
    
    slow = 0  # slow pointer: next position to write a unique element
    
    for fast in range(1, len(nums)):  # fast: scans ahead
        if nums[fast] != nums[slow]:   # found a new unique element
            slow += 1
            nums[slow] = nums[fast]    # write it to the slow position
    
    return slow + 1  # number of unique elements

# Time: O(n), Space: O(1)
print(remove_duplicates([1,1,2,3,3,4]))  # 4, array becomes [1,2,3,4,...]

# ── PATTERN 3: Palindrome check ─────────────────────────────────
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

Module 1.3 — Sliding Window

Sliding window is used when you need to find a subarray or substring satisfying some condition. Instead of recomputing every subarray from scratch (O(n²)), you "slide" a window — add one element on the right, remove one on the left — maintaining state incrementally.

Two types:

  • Fixed-size window: window has a constant size k. Slide it across the array.
  • Variable-size window: expand right until a condition is violated, then shrink from the left.
# ── FIXED WINDOW: Max sum of subarray of size k ─────────────────

def max_subarray_sum_k(nums, k):
    n = len(nums)
    if n < k:
        return -1
    
    # Build initial window [0..k-1]
    window_sum = sum(nums[:k])
    best = window_sum
    
    # Slide: add nums[i], remove nums[i-k]
    for i in range(k, n):
        window_sum += nums[i] - nums[i - k]  # O(1) update!
        best = max(best, window_sum)
    
    return best

print(max_subarray_sum_k([2, 1, 5, 1, 3, 2], 3))  # 9  (5+1+3)
# Time: O(n),  Space: O(1)

# ── VARIABLE WINDOW: Longest substring without repeating chars ──
# Framework Step 1: Input = string s. Output = int (max length).
# Framework Step 2: "Longest substring" → sliding window.
# Framework Step 3: Brute = try all O(n²) substrings → O(n³). Optimize with window.

def length_of_longest_substring(s: str) -> int:
    """
    Find length of longest substring without repeating characters.
    Time: O(n), Space: O(min(m, n)) where m = charset size.
    """
    seen = {}   # char → most recent index we saw it
    left = 0
    best = 0
    
    for right in range(len(s)):
        char = s[right]
        
        # If char is already in window AND its last occurrence is within window
        if char in seen and seen[char] >= left:
            # Shrink window: move left past the duplicate
            left = seen[char] + 1
        
        # Always update the char's most recent position
        seen[char] = right
        
        # Update best window size
        best = max(best, right - left + 1)
    
    return best

# Tests:
print(length_of_longest_substring("abcabcbb"))  # 3 ("abc")
print(length_of_longest_substring("bbbbb"))      # 1 ("b")
print(length_of_longest_substring(""))            # 0 (empty edge case)

Module 1.4 — Linked Lists

A linked list is a chain of nodes where each node holds a value and a pointer to the next node. Unlike arrays, there's no index access — you must traverse from the head. Insertions/deletions are O(1) if you have a reference to the node, but lookup is O(n).

# ── NODE DEFINITION — you'll write this in every linked list problem ─
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next  # pointer to next node (None = end of list)

# ── BUILD A LIST: 1 → 2 → 3 → 4 → 5 ────────────────────────────
def build_list(values):
    dummy = ListNode(0)  # dummy head makes insertion cleaner
    curr = dummy
    for v in values:
        curr.next = ListNode(v)
        curr = curr.next
    return dummy.next

# ── TRAVERSE A LIST ──────────────────────────────────────────────
def print_list(head):
    curr = head
    result = []
    while curr:
        result.append(curr.val)
        curr = curr.next
    print(" → ".join(map(str, result)))

# ── KEY TECHNIQUE: Reverse a Linked List ─────────────────────────
# Framework applied: Input = head of list. Output = head of reversed list.
# Pattern: pointer manipulation, three variables: prev, curr, next_node

def reverse_list(head):
    """
    Iteratively reverse a linked list.
    Time: O(n), Space: O(1)
    """
    prev = None
    curr = head
    
    while curr:
        next_node = curr.next  # save next before we overwrite the pointer
        curr.next = prev       # reverse the link
        prev = curr            # advance prev
        curr = next_node       # advance curr
    
    return prev  # prev is now the new head

# ── KEY TECHNIQUE: Fast & Slow Pointers (Floyd's Algorithm) ──────
# Use: detect cycle, find middle, find kth from end

def has_cycle(head):
    """Detect if a linked list has a cycle. O(n) time, O(1) space."""
    slow = fast = head
    while fast and fast.next:
        slow = slow.next           # moves 1 step
        fast = fast.next.next      # moves 2 steps
        if slow == fast:
            return True           # they met → there's a cycle!
    return False

def find_middle(head):
    """Find middle node. If even length, returns second middle."""
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow  # when fast reaches end, slow is at middle

# ── DUMMY HEAD PATTERN — simplifies edge cases ───────────────────
def delete_node(head, val):
    dummy = ListNode(0)
    dummy.next = head
    curr = dummy
    while curr.next:
        if curr.next.val == val:
            curr.next = curr.next.next  # skip the node
        else:
            curr = curr.next
    return dummy.next

Module 1.5 — Stacks

A stack is a Last-In-First-Out (LIFO) structure. Think of a stack of plates — you only add to or remove from the top. In Python, use a list as a stack (append = push, pop() = pop).

Use when: matching brackets, "undo" operations, converting recursion to iteration, monotonic problems (next greater element).

# ── STACK BASICS ─────────────────────────────────────────────────
stack = []
stack.append(1)    # push   O(1)
stack.append(2)
stack.append(3)
print(stack[-1])    # peek   O(1)  → 3
stack.pop()         # pop    O(1)  → removes 3
print(bool(stack))  # is non-empty → True

# ── CLASSIC: Valid Parentheses ────────────────────────────────────
# Framework Step 1: Input = string of brackets. Output = bool.
# Framework Step 2: "matching brackets" → Stack.
# Framework Step 3: Push open brackets, pop and verify on close brackets.

def is_valid(s: str) -> bool:
    """
    Return True if brackets are correctly matched and nested.
    Time: O(n), Space: O(n)
    """
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    
    for ch in s:
        if ch in '([{':
            stack.append(ch)           # push open bracket
        elif ch in pairs:
            # Close bracket: stack must be non-empty and top must match
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
    
    return len(stack) == 0  # stack must be empty at end

print(is_valid("()[]{}"))   # True
print(is_valid("([)]"))     # False
print(is_valid("((("))      # False — stack not empty at end

# ── MONOTONIC STACK: Next Greater Element ───────────────────────
# For each element, find the next element in the array that is greater.

def next_greater(nums):
    n = len(nums)
    result = [-1] * n   # default: no greater element found
    stack = []           # stores indices (not values)
    
    for i in range(n):
        # Pop all elements smaller than current — current is their answer
        while stack and nums[stack[-1]] < nums[i]:
            idx = stack.pop()
            result[idx] = nums[i]
        stack.append(i)
    
    return result

print(next_greater([2, 1, 2, 4, 3]))  # [4, 2, 4, -1, -1]
# Time: O(n) amortized — each element pushed and popped at most once

Module 1.6 — Queues and Deques

A queue is First-In-First-Out (FIFO). Think of a checkout line. In Python, never use a list as a queue — list.pop(0) is O(n). Use collections.deque which has O(1) operations on both ends.

from collections import deque

# ── DEQUE BASICS ─────────────────────────────────────────────────
q = deque()
q.append(1)        # enqueue right  O(1)
q.append(2)
q.appendleft(0)    # enqueue left   O(1)
print(q)            # deque([0, 1, 2])
q.popleft()         # dequeue left   O(1)  → removes 0
q.pop()             # dequeue right  O(1)  → removes 2

# ── BFS TEMPLATE (preview — full BFS in Level 2) ─────────────────
# Queues are the backbone of Breadth-First Search.

def bfs_template(graph, start):
    visited = {start}
    q = deque([start])
    
    while q:
        node = q.popleft()         # process node
        print(node)
        
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                q.append(neighbor)  # enqueue unvisited neighbors

# ── SLIDING WINDOW MAXIMUM using Deque (Advanced preview) ────────
# Find max of every window of size k in O(n) — crucial Medium pattern

def sliding_window_max(nums, k):
    dq = deque()   # stores indices, front = index of current max
    result = []
    
    for i, num in enumerate(nums):
        # Remove indices outside window
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        # Remove indices whose values are less than current (they can't be max)
        while dq and nums[dq[-1]] < num:
            dq.pop()
        
        dq.append(i)
        
        if i >= k - 1:
            result.append(nums[dq[0]])  # front is always the max
    
    return result

print(sliding_window_max([1,3,-1,-3,5,3,6,7], 3))  # [3,3,5,5,6,7]

Module 2.1 — Binary Trees

A binary tree is a node where each node has at most two children (left and right). Trees are almost always solved recursively — your base case is if not node: return. Every tree algorithm follows one of three traversal orders: in-order, pre-order, or post-order.

# ── TREE NODE DEFINITION ────────────────────────────────────────
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

# ── THREE TRAVERSALS (commit to memory) ──────────────────────────
def inorder(root):    # Left → Node → Right  (gives sorted order in BST!)
    if not root: return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def preorder(root):   # Node → Left → Right  (copy/serialize tree)
    if not root: return []
    return [root.val] + preorder(root.left) + preorder(root.right)

def postorder(root):  # Left → Right → Node  (delete tree, evaluate expression)
    if not root: return []
    return postorder(root.left) + postorder(root.right) + [root.val]

# ── KEY METRIC: Height / Depth ────────────────────────────────────
def height(root):
    if not root: return 0                     # base case
    return 1 + max(height(root.left), height(root.right))

# ── LEVEL ORDER TRAVERSAL (BFS on trees) ─────────────────────────
from collections import deque

def level_order(root):
    if not root: return []
    result, q = [], deque([root])
    
    while q:
        level_size = len(q)
        level = []
        for _ in range(level_size):   # process exactly one level at a time
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        result.append(level)
    
    return result

# ── WORKED EXAMPLE: Maximum Depth of Binary Tree (#104) ──────────
# Framework Step 1: Input=root, Output=int (max depth)
# Framework Step 2: Tree height = recursive structure → DFS
# Framework Step 3: depth(node) = 1 + max(depth(left), depth(right))

def max_depth(root) -> int:
    if not root: return 0          # base case: null node has depth 0
    left_depth  = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)
# Time: O(n), Space: O(h) where h = height (O(log n) balanced, O(n) worst)

Module 2.2 — Binary Search Trees (BST)

A BST is a binary tree where for every node: all values in left subtree < node.val < all values in right subtree. This property allows O(log n) search, insert, and delete on balanced trees. In-order traversal of a BST always gives sorted order — this is a key interview insight.

def search_bst(root, target):
    """Search BST for target. O(log n) balanced, O(n) worst case."""
    if not root or root.val == target:
        return root
    if target < root.val:
        return search_bst(root.left, target)
    return search_bst(root.right, target)

def is_valid_bst(root, lo=float('-inf'), hi=float('inf')):
    """Validate BST: every node must be within (lo, hi) bounds."""
    if not root: return True
    if not (lo < root.val < hi): return False
    return (is_valid_bst(root.left, lo, root.val) and
            is_valid_bst(root.right, root.val, hi))

def kth_smallest(root, k):
    """Find kth smallest in BST using in-order traversal."""
    stack, curr = [], root
    while stack or curr:
        while curr:
            stack.append(curr)
            curr = curr.left
        curr = stack.pop()
        k -= 1
        if k == 0: return curr.val
        curr = curr.right

Module 2.3 — Heaps (Priority Queues)

A heap is a complete binary tree where the parent is always ≤ (min-heap) or ≥ (max-heap) its children. Python's heapq is a min-heap — the smallest element is always at index 0. To simulate a max-heap, negate values.

import heapq

# ── MIN-HEAP BASICS ───────────────────────────────────────────────
heap = [3, 1, 4, 1, 5, 9, 2]
heapq.heapify(heap)        # O(n) — convert list to heap in-place
print(heap[0])              # 1  — peek at minimum, O(1)
heapq.heappush(heap, 0)    # O(log n) — add element
heapq.heappop(heap)        # O(log n) — remove and return minimum

# ── MAX-HEAP: negate values ───────────────────────────────────────
max_heap = [-x for x in [3, 1, 4, 1, 5, 9, 2]]
heapq.heapify(max_heap)
print(-max_heap[0])        # 9 — the maximum

# ── PATTERN: K Largest Elements ──────────────────────────────────
# Framework Step 2: "k largest" keyword → min-heap of size k
# Maintain a min-heap: if new element > heap min, swap it in.

def k_largest(nums, k):
    """Return the k largest elements. O(n log k) time."""
    heap = nums[:k]
    heapq.heapify(heap)          # min-heap of size k
    
    for num in nums[k:]:
        if num > heap[0]:          # larger than current minimum
            heapq.heapreplace(heap, num)  # pop min, push num
    
    return heap                    # contains k largest (unsorted)

# ── PATTERN: K-th Largest Element (#215) ──────────────────────────
def find_kth_largest(nums, k):
    return heapq.nlargest(k, nums)[-1]   # O(n log k)

# OR: maintain min-heap of size k, return heap[0]
def find_kth_largest_v2(nums, k):
    heap = []
    for n in nums:
        heapq.heappush(heap, n)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]

Module 2.4 — Tries (Prefix Trees)

A trie is a tree where each node represents a character, and paths from root to a marked node spell out a word. Tries are used for autocomplete, spell check, and prefix-matching problems.

class TrieNode:
    def __init__(self):
        self.children = {}     # char → TrieNode
        self.is_end = False  # True if a word ends here

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        """Insert word into trie. O(m) where m = word length."""
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word) -> bool:
        """Return True if exact word is in trie. O(m)."""
        node = self.root
        for ch in word:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return node.is_end

    def starts_with(self, prefix) -> bool:
        """Return True if any word in trie starts with prefix. O(m)."""
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return False
            node = node.children[ch]
        return True

Module 2.5 — Graphs: BFS and DFS

A graph is a set of nodes connected by edges. Unlike trees, graphs can have cycles and multiple paths between nodes. The two fundamental traversal algorithms are BFS (breadth-first, level by level) and DFS (depth-first, go as deep as possible before backtracking).

BFS — Use When

  • Shortest path in unweighted graph
  • Level-by-level tree traversal
  • "Minimum steps/hops to reach"

DFS — Use When

  • Detect cycles
  • Find all paths
  • Topological sort, connected components
  • Flood fill / island counting
# ── GRAPH REPRESENTATION: Adjacency List ─────────────────────────
graph = {
    0: [1, 2],
    1: [0, 3],
    2: [0, 4],
    3: [1],
    4: [2]
}

# ── BFS TEMPLATE ─────────────────────────────────────────────────
from collections import deque

def bfs(graph, start):
    visited = {start}
    q = deque([start])
    order = []
    
    while q:
        node = q.popleft()
        order.append(node)
        
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                q.append(neighbor)
    
    return order

# ── DFS TEMPLATE (recursive) ──────────────────────────────────────
def dfs(graph, node, visited=None):
    if visited is None: visited = set()
    visited.add(node)
    
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)
    
    return visited

# ── CLASSIC: Number of Islands (#200) ─────────────────────────────
# Framework Step 1: Input=2D grid of '1'/'0'. Output=int (island count).
# Framework Step 2: "Grid / island" → BFS or DFS from each unvisited land cell.
# Framework Step 3: For each unvisited '1', do DFS and mark all reachable '1's visited.

def num_islands(grid) -> int:
    if not grid: return 0
    rows, cols = len(grid), len(grid[0])
    count = 0
    
    def dfs(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] != '1':
            return
        grid[r][c] = '0'  # mark as visited (in-place)
        dfs(r+1, c); dfs(r-1, c); dfs(r, c+1); dfs(r, c-1)
    
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                dfs(r, c)   # flood-fill the whole island
                count += 1
    
    return count
# Time: O(m×n), Space: O(m×n) recursion stack worst case

Module 2.6 — Backtracking

Backtracking is DFS on a decision tree. At each step, you make a choice, recurse, then un-make the choice (backtrack). This explores all possibilities while pruning branches that can't lead to a valid solution. Pattern: choose → explore → un-choose.

# ── BACKTRACKING TEMPLATE ─────────────────────────────────────────
def backtrack(state, choices, result):
    if is_solution(state):
        result.append(state[:])  # copy, not reference!
        return
    
    for choice in choices:
        if is_valid(choice, state):
            state.append(choice)      # CHOOSE
            backtrack(state, choices, result)  # EXPLORE
            state.pop()               # UN-CHOOSE (backtrack)

# ── CLASSIC: Subsets (#78) ────────────────────────────────────────
def subsets(nums):
    result = []
    
    def backtrack(start, current):
        result.append(current[:])  # every state is a valid subset
        
        for i in range(start, len(nums)):
            current.append(nums[i])   # choose
            backtrack(i + 1, current) # explore (next element forward only)
            current.pop()             # un-choose
    
    backtrack(0, [])
    return result

print(subsets([1, 2, 3]))
# [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]

# ── CLASSIC: Permutations (#46) ───────────────────────────────────
def permutations(nums):
    result = []
    
    def backtrack(current, remaining):
        if not remaining:
            result.append(current[:])
            return
        for i, num in enumerate(remaining):
            current.append(num)
            backtrack(current, remaining[:i] + remaining[i+1:])
            current.pop()
    
    backtrack([], nums)
    return result

Module 3.1 — Dynamic Programming (DP)

DP is a technique for optimization and counting problems where larger answers are built from smaller subproblems. The two styles are top-down (memoization) and bottom-up (tabulation). Always identify the DP state and transition before writing a single line of code.

💡
The 3-Question DP Litmus Test

(1) Does the problem ask for max/min/count/true-false? (2) Are the same subproblems solved repeatedly? (3) Does optimal answer to the whole depend on optimal answers to parts? All three → DP.

DP Pattern 1: 1D DP — Climbing Stairs

# ── CLIMBING STAIRS (#70) ─────────────────────────────────────────
# Problem: n stairs, each step you can climb 1 or 2. How many distinct ways?
# Framework Step 2: "how many ways" + overlapping subproblems → DP.
# Recurrence: ways(n) = ways(n-1) + ways(n-2)  ← same as Fibonacci!

# BOTTOM-UP (preferred in interviews)
def climb_stairs(n: int) -> int:
    if n <= 2: return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b   # roll forward
    return b
# Time: O(n), Space: O(1)

# ── COIN CHANGE (#322) — unbounded knapsack ───────────────────────
# Fewest coins to make amount. Coins can be reused.
# State: dp[a] = fewest coins to make amount a
# Transition: dp[a] = min(dp[a], dp[a - coin] + 1) for each coin

def coin_change(coins, amount) -> int:
    INF = float('inf')
    dp = [INF] * (amount + 1)
    dp[0] = 0          # base case: 0 coins to make 0
    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a:
                dp[a] = min(dp[a], dp[a - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1

print(coin_change([1,5,10,25], 41))  # 4  (25+10+5+1)

DP Pattern 2: 2D DP — LCS and Edit Distance

# ── LONGEST COMMON SUBSEQUENCE (#1143) ────────────────────────────
# State: dp[i][j] = LCS length of text1[0..i-1] and text2[0..j-1]
# Transition:
#   chars match  → dp[i][j] = dp[i-1][j-1] + 1
#   chars differ → dp[i][j] = max(dp[i-1][j], dp[i][j-1])

def lcs(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

# ── EDIT DISTANCE (#72) — Levenshtein ────────────────────────────
# Min operations (insert, delete, replace) to convert word1 → word2.
# State: dp[i][j] = min edits for word1[0..i-1] → word2[0..j-1]

def min_distance(word1: str, word2: str) -> int:
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i   # delete all of word1
    for j in range(n + 1): dp[0][j] = j   # insert all of word2
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i-1] == word2[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j],    # delete
                                    dp[i][j-1],    # insert
                                    dp[i-1][j-1])  # replace
    return dp[m][n]

print(min_distance("horse", "ros"))   # 3

DP Pattern 3: 0/1 Knapsack + LIS

# ── PARTITION EQUAL SUBSET SUM (#416) — 0/1 knapsack ─────────────
# Can we partition nums into two subsets with equal sum?
# Equivalent: can we find a subset that sums to total//2?

def can_partition(nums) -> bool:
    total = sum(nums)
    if total % 2 != 0: return False
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True            # base: sum 0 always reachable
    for num in nums:
        for j in range(target, num - 1, -1):  # iterate backwards (0/1 knapsack!)
            dp[j] = dp[j] or dp[j - num]
    return dp[target]

# ── LONGEST INCREASING SUBSEQUENCE (#300) ─────────────────────────
import bisect

def length_of_lis(nums) -> int:
    tails = []   # tails[i] = smallest tail of all IS of length i+1
    for num in nums:
        pos = bisect.bisect_left(tails, num)
        if pos == len(tails):
            tails.append(num)   # extend longest IS
        else:
            tails[pos] = num      # replace — maintains smallest tails
    return len(tails)
# Time: O(n log n), Space: O(n)

Module 3.2 — Greedy Algorithms

Greedy picks the locally optimal choice at each step and never reconsiders. Faster than DP but only valid when a greedy choice property holds. Always ask: can I prove greedy is safe here?

# ── JUMP GAME (#55) ───────────────────────────────────────────────
# Greedy insight: track farthest reachable index at each step.
def can_jump(nums) -> bool:
    max_reach = 0
    for i, jump in enumerate(nums):
        if i > max_reach: return False
        max_reach = max(max_reach, i + jump)
    return True
# Time: O(n), Space: O(1)

# ── MERGE INTERVALS (#56) ─────────────────────────────────────────
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]
    for start, end in intervals[1:]:
        if start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged

# ── MEETING ROOMS II (#253) — min rooms needed ────────────────────
import heapq

def min_meeting_rooms(intervals) -> int:
    if not intervals: return 0
    intervals.sort(key=lambda x: x[0])
    heap = []   # min-heap of end times
    for start, end in intervals:
        if heap and heap[0] <= start:
            heapq.heapreplace(heap, end)   # reuse freed room
        else:
            heapq.heappush(heap, end)      # new room needed
    return len(heap)

Module 3.3 — Union-Find (Disjoint Set Union)

Efficiently answers: "Are these two nodes connected?" and "Merge these components." Essential for cycle detection and Kruskal's MST.

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank   = [0] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # path compression
        return self.parent[x]

    def union(self, x, y) -> bool:
        rx, ry = self.find(x), self.find(y)
        if rx == ry: return False   # already connected → cycle!
        if self.rank[rx] < self.rank[ry]: rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]: self.rank[rx] += 1
        return True

    def connected(self, x, y) -> bool:
        return self.find(x) == self.find(y)

Module 3.4 — Advanced Graph Algorithms

Dijkstra's Shortest Path

def dijkstra(graph, start):
    """
    Shortest path from start in a weighted graph.
    graph: {node: [(neighbor, weight), ...]}
    Time: O((V + E) log V)
    """
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    heap = [(0, start)]

    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]: continue   # stale entry
        for neighbor, weight in graph[node]:
            nd = d + weight
            if nd < dist[neighbor]:
                dist[neighbor] = nd
                heapq.heappush(heap, (nd, neighbor))
    return dist

Topological Sort — Kahn's Algorithm

from collections import deque

def topo_sort(n, prerequisites):
    """Returns topological order, or [] if a cycle exists."""
    graph  = [[] for _ in range(n)]
    in_deg = [0] * n
    for a, b in prerequisites:
        graph[b].append(a); in_deg[a] += 1

    q = deque([i for i in range(n) if in_deg[i] == 0])
    order = []
    while q:
        node = q.popleft(); order.append(node)
        for nei in graph[node]:
            in_deg[nei] -= 1
            if in_deg[nei] == 0: q.append(nei)
    return order if len(order) == n else []

Module 3.5 — Bit Manipulation

# ── CORE BIT OPERATIONS ───────────────────────────────────────────
# n & 1        → check if odd
# n >> 1       → floor divide by 2
# n << 1       → multiply by 2
# n & (n-1)    → clear lowest set bit (is_power_of_two: n>0 and this==0)
# a ^ b        → XOR: bits differ → 1. a^a=0, a^0=a

def single_number(nums) -> int:
    """Find the one non-duplicate element. O(n) time, O(1) space."""
    result = 0
    for n in nums:
        result ^= n    # duplicates cancel: a^a=0, leaving the lone element
    return result

print(single_number([4, 1, 2, 1, 2]))  # 4

def count_bits_set(n) -> int:
    count = 0
    while n:
        n &= n - 1   # clear lowest set bit
        count += 1
    return count

def is_power_of_two(n) -> bool:
    return n > 0 and (n & (n - 1)) == 0

Module D.1 — Matrix Operations (NumPy Fundamentals)

Matrix operations underpin virtually every ML algorithm. You should be able to implement these without NumPy first, then know the vectorized NumPy form.

import numpy as np

# ── MATRIX MULTIPLICATION (implement from scratch first) ──────────
def matmul_naive(A, B):
    """
    Multiply matrix A (m×k) by B (k×n) → result (m×n).
    Time: O(m×k×n)
    """
    m, k = len(A), len(A[0])
    k2, n = len(B), len(B[0])
    assert k == k2, "Incompatible dimensions"

    C = [[0.0] * n for _ in range(m)]
    for i in range(m):
        for j in range(n):
            for p in range(k):
                C[i][j] += A[i][p] * B[p][j]
    return C

Module D.2 — Implement Softmax and Cross-Entropy from Scratch

These two functions are the foundation of classification in deep learning. You will be asked to implement them — and explain the numerical stability trick for softmax.

# ── SOFTMAX ───────────────────────────────────────────────────────
# Converts a vector of raw scores (logits) into probabilities.
# Framework Step 1: Input = 1D array of logits. Output = probabilities summing to 1.

def softmax_naive(x):
    """NAIVE — numerically unstable for large values."""
    e = np.exp(x)
    return e / np.sum(e)

def softmax_stable(x):
    """
    NUMERICALLY STABLE softmax.
    Subtract max(x) before exponentiating — doesn't change result
    (dividing numerator and denominator by e^max cancels), but
    prevents overflow when values are large (e.g. x=[1000, 999]).
    """
    x = x - np.max(x)   # KEY trick: shift by max
    e = np.exp(x)
    return e / np.sum(e)

logits = np.array([2.0, 1.0, 0.1])
print(softmax_stable(logits))   # [0.659, 0.242, 0.099]

# ── CROSS-ENTROPY LOSS ────────────────────────────────────────────
# Measures how far predicted probabilities are from true labels.

def cross_entropy_loss(probs, true_label):
    """
    probs: softmax output probabilities (1D array)
    true_label: integer index of correct class
    Returns: scalar loss value
    """
    eps = 1e-9   # avoid log(0)
    return -np.log(probs[true_label] + eps)

probs = softmax_stable(logits)
loss  = cross_entropy_loss(probs, true_label=0)
print(f"Loss: {loss:.4f}")   # ~0.4181

Module D.3 — K-Means Clustering from Scratch

K-means is one of the most common "implement from scratch" ML interview questions. Know the algorithm cold: initialize centroids → assign points → update centroids → repeat until convergence.

# ── K-MEANS FROM SCRATCH ──────────────────────────────────────────
# Framework applied:
# Step 1: Input = 2D array of points (n×d), int k. Output = cluster labels + centroids.
# Step 2: Iterative assignment — no single "pattern", but structured algorithm.
# Step 3: Brute = random restarts. Optimal = k-means++ init (not required here).

def kmeans(X, k, max_iters=100, tol=1e-4):
    """
    K-Means clustering.
    X: np.array of shape (n_samples, n_features)
    k: number of clusters
    Returns: (labels, centroids)
    """
    n, d = X.shape

    # ── Step 1: Initialize centroids randomly from data points ───
    idx = np.random.choice(n, k, replace=False)
    centroids = X[idx].copy()   # shape: (k, d)

    for _ in range(max_iters):
        # ── Step 2: Assign each point to nearest centroid ─────────
        # Euclidean distance: (n,1,d) - (1,k,d) → (n,k,d) → sum over d → (n,k)
        dists = np.linalg.norm(X[:, np.newaxis, :] - centroids[np.newaxis, :, :], axis=2)
        labels = np.argmin(dists, axis=1)   # shape: (n,)

        # ── Step 3: Update centroids to mean of assigned points ───
        new_centroids = np.array([X[labels == j].mean(axis=0)
                                    if np.any(labels == j) else centroids[j]
                                    for j in range(k)])

        # ── Step 4: Check convergence ─────────────────────────────
        if np.linalg.norm(new_centroids - centroids) < tol:
            break
        centroids = new_centroids

    return labels, centroids

               np.random.randn(50, 2) + [5, 5]])

print("Centroids:", centroids)
# Should show two centroids near [0,0] and [5,5]

Module D.4 — Neural Network Forward Pass from Scratch

Implementing a forward pass tests whether you understand what a neural network actually computes — not just how to call model.fit().

# ── SINGLE HIDDEN LAYER NEURAL NETWORK FORWARD PASS ──────────────
# Architecture: Input → Linear → ReLU → Linear → Softmax → Loss

def relu(z):
    return np.maximum(0, z)

def forward_pass(X, W1, b1, W2, b2):
    """
    X:  input  (batch_size, input_dim)
    W1: weights layer 1  (input_dim, hidden_dim)
    b1: bias layer 1     (hidden_dim,)
    W2: weights layer 2  (hidden_dim, output_dim)
    b2: bias layer 2     (output_dim,)

    Returns: output probabilities (batch_size, output_dim)
    """
    # Layer 1: linear + activation
    z1 = X @ W1 + b1         # (batch, hidden_dim)
    a1 = relu(z1)            # (batch, hidden_dim)

    # Layer 2: linear + softmax
    z2 = a1 @ W2 + b2        # (batch, output_dim)
    probs = np.array([softmax_stable(row) for row in z2])  # (batch, output_dim)

    return probs, (z1, a1, z2)   # also return intermediates for backprop

# Tiny example:
np.random.seed(0)
batch_size, input_dim, hidden_dim, output_dim = 4, 3, 5, 2
X  = np.random.randn(batch_size, input_dim)
W1 = np.random.randn(input_dim, hidden_dim) * 0.1
b1 = np.zeros(hidden_dim)
W2 = np.random.randn(hidden_dim, output_dim) * 0.1
b2 = np.zeros(output_dim)

probs, cache = forward_pass(X, W1, b1, W2, b2)
print("Output probabilities:", probs)
print("Each row sums to 1:", np.allclose(probs.sum(axis=1), 1.0))

Module D.5 — Scaled Dot-Product Attention (Transformer Core)

Implementing attention is increasingly common in AI Engineer interviews at companies building LLM-adjacent products. This tests both ML knowledge and NumPy fluency.

# ── SCALED DOT-PRODUCT ATTENTION ─────────────────────────────────
# Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) × V
# Q: queries  (seq_len, d_k)
# K: keys     (seq_len, d_k)
# V: values   (seq_len, d_v)

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Framework Step 1: Q,K,V are matrices. Output = weighted sum of values.
    Framework Step 3: 4 steps: score → scale → (mask) → softmax → weighted sum.
    Time: O(n^2 * d) — quadratic in sequence length (the core transformer bottleneck).
    """
    d_k = Q.shape[-1]

    # Step 1: Compute raw attention scores
    scores = Q @ K.T          # (seq_len, seq_len)  — how much each query attends to each key

    # Step 2: Scale by sqrt(d_k) — prevents dot products from growing too large
    scores = scores / np.sqrt(d_k)

    # Step 3: Apply mask (optional) — used in causal/decoder attention
    if mask is not None:
        scores = scores + mask * (-1e9)   # large negative → softmax ≈ 0

    # Step 4: Softmax over key dimension → attention weights
    weights = np.array([softmax_stable(row) for row in scores])   # (seq_len, seq_len)

    # Step 5: Weighted sum of values
    output = weights @ V      # (seq_len, d_v)

    return output, weights

# Test:
np.random.seed(42)
seq_len, d_k, d_v = 4, 8, 8
Q = np.random.randn(seq_len, d_k)
K = np.random.randn(seq_len, d_k)
V = np.random.randn(seq_len, d_v)

output, weights = scaled_dot_product_attention(Q, K, V)
print("Output shape:", output.shape)     # (4, 8)
print("Weights sum to 1 per row:", np.allclose(weights.sum(axis=1), 1.0))

# ── CAUSAL MASK (for decoder self-attention) ─────────────────────
# Prevents position i from attending to positions j > i (future tokens)
causal_mask = np.triu(np.ones((seq_len, seq_len)), k=1)   # upper triangle = 1
output_causal, _ = scaled_dot_product_attention(Q, K, V, mask=causal_mask)
print("Causal output shape:", output_causal.shape)
