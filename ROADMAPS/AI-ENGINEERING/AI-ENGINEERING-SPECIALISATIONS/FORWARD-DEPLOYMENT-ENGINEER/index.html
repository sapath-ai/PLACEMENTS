02.02 FDE FAILURE LAB — DEBUG THE SYSTEM, NOT JUST THE CODE

Incident: Latency Cascade

  • Trigger: downstream model API slows 3×.
  • Observe: p95 latency, queue depth, retries, saturation.
  • Reason: retry amplification → worker starvation → request timeout cascade.
  • Response: deadlines + circuit breaker + bounded retries + load shedding.

Incident: Duplicate Execution

  • Trigger: queue redelivers a payment-like workflow.
  • Observe: duplicate event IDs and repeated tool calls.
  • Reason: at-least-once delivery is behaving as designed.
  • Response: idempotency key + durable state transition + dedupe store.

Incident: Split-Brain Behavior

  • Trigger: two workers believe they own the same job.
  • Observe: conflicting writes / leader heartbeat anomalies.
  • Reason: lease/coordination failure under network partition.
  • Response: fencing token + lease expiry + safe recovery.

Incident: Cache Stampede

  • Trigger: hot cache entries expire together during peak traffic.
  • Observe: origin QPS, cache miss ratio, lock contention, p99 latency.
  • Reason: synchronized misses overload the source of truth.
  • Response: request coalescing + jittered TTL + stale-while-revalidate + bounded origin concurrency.

Incident: Queue Starvation

  • Trigger: one high-volume tenant monopolizes workers.
  • Observe: per-tenant queue depth, service time, oldest-message age.
  • Reason: shared worker capacity lacks fairness controls.
  • Response: weighted scheduling + quotas + tenant isolation + overload signaling.

Incident: Dependency Brownout

  • Trigger: upstream remains reachable but error/latency rises sharply.
  • Observe: dependency SLO, timeout rate, retry amplification, saturation.
  • Reason: partial degradation is hidden by binary up/down health checks.
  • Response: adaptive admission control + fallback + dependency budget + progressive recovery.

03.02 AGENT FAILURE LAB — BREAK THE LOOP, NOT THE CUSTOMER

Incident: Infinite Tool Loop

  • Trigger: agent repeatedly retries a failing tool.
  • Observe: trajectory length, repeated tool IDs, latency and token spend.
  • Reason: no termination policy and no failure budget.
  • Response: attempt budget + circuit break + deterministic fallback + escalation.

Incident: Bad Tool Choice

  • Trigger: agent selects a destructive tool when a read-only path exists.
  • Observe: tool selection, permission scope, action class.
  • Reason: capability surface is too broad.
  • Response: least-privilege tools + policy gate + typed action classes + approval.

Incident: Context Collapse

  • Trigger: long workflow causes critical context to disappear.
  • Observe: context size, retrieval misses, state loss, task success.
  • Reason: uncontrolled history growth.
  • Response: summarization + state checkpoint + prioritized retrieval + context budget.

Incident: Partial Multi-Agent Completion

  • Trigger: two specialists finish, one fails after a side effect.
  • Observe: agent state, action log, compensation status.
  • Reason: orchestration lacked transactional recovery semantics.
  • Response: durable state + compensation + retry-safe handoff + human escalation.

Incident: Tool Poisoning

  • Trigger: retrieved instructions attempt to redirect a privileged action.
  • Observe: source provenance, requested capability, policy decision.
  • Reason: untrusted context influenced privileged execution.
  • Response: trust boundary + capability allowlist + policy gate + approval.

Incident: Silent Quality Regression

  • Trigger: model update preserves latency but task success falls.
  • Observe: golden trajectories, tool accuracy, success and escalation.
  • Reason: release lacked behavior-level regression gates.
  • Response: golden set + regression suite + threshold + rollback.

13.04 FAILURE LAB — BREAK THE INTERVIEW BEFORE IT BREAKS YOU

Overcoding

  • Failure: starts implementing before clarifying the problem.
  • Recovery: stop, state assumptions, ask for missing constraints, redefine the first slice.

Architecture Fog

  • Failure: names technologies without explaining system boundaries.
  • Recovery: draw request/data/control paths and identify state, failure and ownership boundaries.

Portfolio Bluff

  • Failure: cannot explain an implementation detail from a flagship project.
  • Recovery: rehearse personal contribution, metrics, incidents and trade-offs until every claim is defensible.

Customer Collision

  • Failure: chooses technically elegant solution that violates customer constraints.
  • Recovery: surface the constraint, offer alternatives, quantify trade-offs and agree on a decision owner.
