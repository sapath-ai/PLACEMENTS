LLM C++ Failure Patterns
✓
Dangling references: LLMs return references to temporaries or stack-allocated objects
✓
Incorrect template instantiation: subtle SFINAE errors that compile but behave wrongly
✓
Off-by-one in container iteration: .end() vs .back(), size_t underflow
✓
Wrong memory ordering in atomics: using relaxed when acquire/release is needed
✓
Iterator invalidation: erasing from vector/map while iterating
✓
Incorrect move: using std::move on objects still referenced elsewhere
✓
Mutex misuse: locking wrong mutex, forgetting to lock, double-lock deadlock
✓
Shared_ptr cycles: circular ownership causing memory leaks
✓
Signed/unsigned comparison UB: comparing int with size_t incorrectly
✓
Exception unsafety: resource leak when exception thrown mid-construction
Systematic Audit Protocol
Step 1 — Sanitizers first
Always compile AI code with -fsanitize=address,undefined before trusting it. Run every code path through the test suite. Zero sanitizer errors is table stakes.
Step 2 — Ownership audit
Trace every raw pointer and reference. Ask: who owns this? What is its lifetime? Is it possible for this to outlive its source? LLMs routinely get this wrong in non-trivial code.
Step 3 — Concurrency audit
Every shared mutable state must have a documented synchronization mechanism. Run TSan. Manually verify every memory_order argument against the happens-before relationship required.
Step 4 — Edge case stress
Empty inputs, single elements, INT_MAX/INT_MIN values, concurrent access at max thread count, exception thrown at every allocation site. LLMs optimize for the happy path.
Mastery Checkpoint
⬡ Must pass before advancing
Given 5 AI-generated C++ snippets (provided by your mentor or generated fresh), identify all bugs using only static reading + sanitizer output — no running the code first. Write a bug report for each with: bug class, exact line, root cause, and correct fix. Target: catch ≥90% of injected bugs within 30 minutes per snippet.

The Four Capstones
Each project must be: on GitHub, with a real README, CI pipeline, full test suite, and zero sanitizer errors. These are portfolio pieces — they should be things you can walk through live in an interview.
✓
Capstone 1 — Custom Memory Allocator
A general-purpose malloc/free replacement using mmap/sbrk. Must handle: coalescing free blocks, best-fit vs first-fit strategies (switchable at compile time), thread safety with a per-thread cache (tcmalloc-style), and pass the full glibc malloc test suite. Benchmark against system malloc at various allocation patterns.
✓
Capstone 2 — Lock-Free Concurrent Queue (MPMC)
A production-quality multi-producer multi-consumer queue using only std::atomic. No mutexes. Must: handle the ABA problem correctly, support bulk enqueue/dequeue, be verified with TSan under 16-thread stress test, and beat std::mutex queue by ≥2× throughput at 8 threads. Document every memory_order decision with justification.
✓
Capstone 3 — Mini Relational Database Engine
A disk-based key-value store with: a B+ tree index, write-ahead logging for crash recovery, MVCC for snapshot isolation, and a SQL-like query parser for SELECT/INSERT/DELETE. Not a toy — it must survive crash-recovery tests (kill -9 mid-write, restart, verify data). Target: 50K writes/sec on SSD.
✓
Capstone 4 — JIT-Compiled Expression Evaluator
Parse arithmetic + boolean expressions into an AST, generate x86-64 machine code at runtime using direct code emission (no LLVM), mmap it as executable, and call it. Must: handle variables, function calls (sin/cos/pow), and compile 10K expressions in <50ms. The output is a function pointer you call directly.
Mastery Checkpoint — Final
⬡ Elite-level gate
Walk a senior engineer at a top company through any one of your capstone projects — live, without notes, answering questions including: "Why did you choose this data structure?", "What happens if this thread is killed mid-operation?", "How does your allocator behave under memory pressure?", "Where is your biggest performance bottleneck and why?" You should be able to answer all of these from deep understanding, not rehearsed talking points.
