THE ALPHA HYPOTHESIS PROTOCOL

H0 The proposed feature contains no incremental predictive information. H1 The feature contains stable incremental information after controls. 01 DEFINE the economic mechanism. 02 FREEZE the evaluation protocol. 03 RESERVE the final test period. 04 BUILD the baseline. 05 ADD exactly one research change. 06 MEASURE effect size + uncertainty. 07 TEST robustness and negative controls. 08 APPLY costs and capacity constraints. 09 CHECK stability across regimes. 10 REPLICATE on untouched data. 11 DOCUMENT failures. 12 Only then call the result evidence.

THE RESEARCHER'S FIVE QUESTIONS

  1. Why should this relationship exist? A statistical association without mechanism is weak.
  2. How many alternatives were tried? The denominator of the research process matters.
  3. Was the test truly untouched? Any human decision based on it contaminates it.
  4. Does it survive realistic costs? A beautiful gross backtest can be economically worthless.
  5. Does it survive time and regime changes? Stability is more valuable than one spectacular period.

THE WALK-FORWARD CONTRACT

TRAIN ────────────────┐ │ VALID ────────┐ │ ▼ ▼ TEST ───────────────────────► NEXT WINDOW Never: • shuffle temporal observations casually • normalize using future data • tune on the final test period • construct features with revised information • compare dozens of horizons and report only the winner Always: • freeze chronology • fit transforms inside each training window • log every experiment • report stability across windows

TIME-SERIES FAILURE MODES

  • Spurious regression: non-stationary series can appear strongly related.
  • Look-ahead leakage: revised or future information enters the feature.
  • Overlapping labels: adjacent observations share information and distort inference.
  • Regime break: a relationship learned in one market environment disappears.
  • Parameter drift: the optimal model changes over time.
  • Volatility clustering: constant-variance assumptions understate uncertainty.

PERFORMANCE QUESTIONS THAT MATTER

  1. What is actually slow? Never optimize based on intuition when a profiler can answer the question.
  2. Is the workload CPU-bound, memory-bound, I/O-bound or network-bound? The optimization strategy changes completely.
  3. Did the optimization improve median latency but worsen p99? Trading systems care about tails, not just averages.
  4. Did throughput improve at the expense of determinism? A faster but unpredictable system can be worse for execution.
  5. Can you reproduce the benchmark? Performance claims without controlled workloads are engineering anecdotes.
